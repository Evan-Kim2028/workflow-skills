# agent-dash design spec (keep stable)

The dashboard is read by a visual thinker. Every view answers its question with a chart or diagram first; text supports it. Change this file before changing the look, and keep every rule below unless this file changes.

## Layout

- One shell, `static/index.html`, served at `/` and at `/plan`. Vanilla JS, inline SVG. No framework, no CDN, no build step. Mermaid is the vendored file under `static/vendor/`.
- The header and the switcher bar render once. Plan | Execution, and workstream changes, swap the main view in place. The URL is `?view=plan|exec&ws=<ID>`. Back and forward restore that view. `/plan?ws=<ID>` and `/static/index.html?ws=<ID>` still open the right view. The selected workstream stays when the view changes.
- Header: title, live dot, Plan | Execution toggle, Project | Current | Planned | Archive switches, and the one Theme toggle at the far top right (`margin-left:auto`). Every windowed number uses one fixed rolling 24-hour window; the only range control is the time filter bar on top of the Activity over time stack, which zooms its four strips without changing any tile or table window.
- Pinned chrome: while scrolled only one slim row stays pinned (project name, `Overall`, the selected workstream chip when one is selected, one `Workstreams (N)` switcher button, up to three pinned chips; `--pinned-h`, 48 px desktop and 44 px phone). The live pill, both view switches, and the Theme toggle scroll away above it, so nothing resizes on scroll; section anchors carry a matching scroll margin.
- Project name is never truncated: `h1#title` keeps its natural width (`flex:none`, no `max-width`, no ellipsis) and the selected chip and pins shrink (`min-width:0`, clipped) to give way. On phones it may wrap to two lines at a smaller step (13 px) inside the 44 px row, clipped without ellipsis.
- Theme decision (owner feedback): exactly one Theme control, a real `<button id="theme">` with `aria-label` and native keyboard support, sitting in the scrolling top row at the far top right — deliberately NOT in the pinned row, so it is never mistaken for part of the pinned switcher bar. Trade-off accepted: it scrolls away with the top row instead of staying reachable while scrolled; keeping the pinned row to name plus switcher.
- No Sections button: the button, its styles, its click wiring, and its `[` shortcut hint are gone. The section dock stays as a desktop hover rail (the always-visible floating dock expands on CSS hover; Escape closes a `?nav=open` latch). The button was the rail's only UI entry on phones, so phones now have none: the phone shut-rail hiding stays live (verified: no rail in the 390 shots) and the phone `.is-open` overlay serves `?nav=open` only — no other dead phone paths remain.
- Switcher: `Overall` returns to Execution on all workstreams; the `Workstreams (N)` button opens a searchable popover (type to filter by name or id, arrow keys and Enter to pick, Escape closes, `/` opens it from anywhere) listing workstreams in WS number order grouped by state (Active, Paused, Planned, Done, then a collapsed Archived group), each row with a state glyph plus word, progress percent, live-agent dot, a pin star, and the primary quick action on hover and focus. Pins (at most three, viewer-local) also show as small chips in the bar. Completed means total > 0 with done === total, the same rule the Where we are panel uses, read from the server progress object and marked with a ✓ plus words, never color alone. There is no tab strip and no reorder: the old viewer-local tab order retired with the strip it ordered. On phones the switcher is a full-width sheet; the bar keeps the project name wrapped to two lines at 13 px while the pins hide.
- Colors, type, and shared controls (card, tab, pill, chip, legend, tooltip, section heading, details) come from `static/tokens.css`. Plan fragments keep their class names. `--accent`, `--fg2`, `--line`, `--ok`, `--warn`, `--crit`, `--surface`, and `--surface-2` are aliases of the reference palette.
- Execution, top to bottom (Overall): a Pulse card (KPI strip: workstreams in progress, agents running by tool, windowed tokens with prior-day delta and hourly bars, windowed cost with prior-day delta, finished agents by verdict; then the workstream momentum chart, one row per open workstream slowest first: stuck ■, slowing ▼, moving ▲, idle ·, each row with plan progress, an hourly token sparkline on one shared scale, live-agent dots, and last-activity age; a row click (or Enter/Space, chevron shows the state) expands an in-place detail panel under the row — several may stay open at once, open rows persist across re-renders — with an actions line (Open workstream, Plan, the Linear link when the plan carries one), that workstream's progress over time from /api/ws/progress (done as a step line, the 20/40/60/80/100 % milestones as ticks on the x axis, runs per hour as faint bars behind, fetched lazily on first expand and cached per minute, gap as one muted footnote), then tokens by phase as one stacked bar with legend, task counts as number cells, and live agents as a compact table), the Where it goes stacked bar right below the pulse card (tokens by workstream, cost by workstream, tokens by model on one three-way toggle), the aggregated-progress card (program burn-up stacked by workstream plus cumulative tokens/cost on one shared time axis), running-now table (full width), grouped workstream → section → agent with a Section | None toggle, the plan progress map, Activity over time (the tokens, run-timeline, progress-over-time and live-agents stack), then or a compact approved/pending line), workstream cards (plus an Unassigned card when runs have no workstream), Finished (24 h), the usage-by-phase stacked bars (one horizontal stacked bar per workstream), then the "Manage workstreams (N)" disclosure last, closed by default, holding the Current management table (its lifecycle controls and per-row actions are unchanged). The "Where we are" panel and the Linear card are no longer on the overview: "Where we are" stays on the Project home and the plan view, and the Linear card is removed from both Execution views. Stat tiles (one row: agents live now, Agents finished (24 h), Tokens (24 h), Est. cost (24 h)) stay on workstream tabs only; the pulse KPI strip owns the overview numbers so the two never duplicate.
- Workstream tab: the same views filtered to that workstream, plus the plan progress map directly under the tiles, and the usage-by-phase per-day stacked columns below Finished (and its pager). Progress over time is the third strip of the Activity over time stack (right below the run timeline): completion % over time with 20/40/60/80/100% first-cross markers on the stack's shared x axis, with its own 0-100% y axis; on the overall view the same strip shows the project total (all non-archived workstreams weighted by task count).
- Plan view: no approvals section. Approvals stay a file the lead reads (`approvals.json`, `ws approvals`); the owner wants nothing on the page that "needs" them. Under the progress summary the Plan view mounts the same live plan progress map the Execution tab shows: the one planCard renderer over the same `/api/plan` body (replay controls off), refreshed on the same live path.
- Run details open in the right-hand drawer; Escape closes it.
- Lists show the top 5 by default: every table or list that can exceed five rows (Running now, the Current management table, Planned readiness and gated tables, the Archive shelf, the Project home planned shelf and unplanned strip, Where we are, decisions, usage-by-kind rows) renders the first five with one shared disclosure control below it (`static/core/disclosure.js` on `window.AdPage`): a real button, "Show all N \<things\>" / "Show top 5 \<things\>", `aria-expanded` plus `aria-controls`, hidden at five or fewer, state per list in `sessionStorage` (v2 keys, default collapsed — an expanded flag stored under a pre-top-5 key never applies). The Finished (24 h) table and Recently done keep their shared 10-per-page pager instead. The switcher popover, the depends-on chips inside rows, and the small drawer definition list are not capped.
- Section dock (left, floating, macOS-dock style): compact dots that magnify and expand to names on hover, pinned (names always), or hidden (slim edge handle); the mode button cycles them and the choice is remembered. At most five groups.

## Color (reference palette, validated; do not invent hues)

- Categorical slots in fixed order: `--s1` blue, `--s2` orange, `--s3` aqua, `--s4` yellow, `--s5` magenta, `--s6` green, `--s7` violet, `--s8` red, `--s9` bronze, `--s10` cyan, `--s11` lime. Light and dark values are defined once in `:root` and the two dark scopes.
- Entity to color is fixed and never depends on rank: opus `--s1`, haiku `--s2`, sonnet `--s3`, grok `--s4`, muse `--s5`, glm `--s6`, deepseek `--s8`, codex `--s9`, commandcode `--s10`, beam `--s11`, other `--other`. Workstreams take slots in first-seen order from `WSCOL`.
- Status colors are reserved for state and never used as a series: good `--good`, warning `--warning`, serious `--serious`, critical `--critical`. A status color always ships with a word or icon.
- Run outcomes share the status scale in severity order, each with its own color AND glyph AND word (never color alone): pass ✓ `--good` green, partial ◐ `--warning` amber, blocked ⊘ `--serious` orange (verdicts the agent itself reported that send work back: BLOCKED, REQUEST_CHANGES, FIX), died ✕ `--critical` red (the session ended without a verdict: killed, died early, process vanished, quota, reported failure — never a close-out BLOCKED), cancelled ⏹ `--muted` grey (cancelled from outside, e.g. Dagster CANCELED), stalled ◔ `--warning` amber (process alive, no output past the headless idle window), no verdict ○ `--muted` grey (ended unconfirmed, nothing reported). Blocked and died never share a look: blocked pill text uses `--serious-ink` (7.33:1 dark, 6.64:1 light on the card) over `--serious-soft`; died keeps `--critical-ink` over `--critical-soft`. One derivation rules them all (`dash/outcomes.py`, mirrored by `ADM.outcomeOf` in `static/models.js`, exposed as `run.outcome_class`): the Agents finished tile caption ("✓ N pass · ◐ N partial · ⊘ N blocked · ✕ N died", plus cancelled / no-verdict only when present), the run-table status cells and verdict pills, the run-timeline bars and legend (exactly the classes present in the window), the replay legend, and the drawer all read it. Amber/orange/red stay apart under red-green color blindness, and the glyph plus word carry the meaning even where they do not.
- Planning-versus-execution entity colors are fixed: planning `--ph-planning` blue (◆), execution `--ph-execution` green (■), review `--ph-review` orange (▲), coordination `--ph-coordination` violet (●), unclassified `--ph-unclassified` grey (○, the same tone as `--other`). The hues stay apart under red-green color blindness, and every legend pairs a glyph plus a word with its swatch, never color alone.
- Text names things, not numbers: a decision, task, PR, issue or ADR is cited by a brief phrase, with its number optional in parentheses after it. Chips show a task id only beside its title or in its tooltip.
- Text uses ink tokens (`--ink`, `--ink-2`, `--muted`), never a series color.

## Charts

- Every chart has a visible x axis and y axis: an axis line, ticks with labels, and a short title or unit ("tokens", "agents", "time"). A categorical axis labels each category (lane or row names are its tick labels). Build axes only with the shared `axes()` helper in `static/format.js`. Both views call that helper. `tests/test_page_rules.py` fails a chart without it.
- Numbers are compact everywhere: counts and tokens through `fmtN` (Intl compact: 950, 1.2K, 3.4M, 1.5B), money through `fmtUsd` ($0.42, $12, $1.2K), durations through `fmtDur` (45s, 3m 10s, 2h 5m, 2d 3h up to 14d, then 23d, then 1y 12d from 365 days). No raw `toFixed` or `toLocaleString` on numbers outside those helpers.
- One y-axis per chart. Different scales get separate charts or small multiples (live agents over time is one strip per model family, drawn only for families with runs in the window). The Activity over time stack shares one x axis (time) across its four strips with one time filter on top; each strip keeps its own y axis and title, and the x labels draw once at the bottom of the stack. There are no concurrency caps or meters: the owner removed them as unclear. Counts are always scoped to the current view.
- Bars and areas: 2 px surface gap between stacked segments, rounded ends, recessive grid and axes.
- Every chart with two or more series has a legend; every mark has a hover tooltip; bars and timeline rows open details on click.
- Timeline bars with file-time clocks (`clock_source = mtime`) are hatched, never solid.
- Plan progress map: sections in columns, arrows mean "waits on": section arrows between tiles, task arrows between chips (solid when the prerequisite is done, dashed while it waits, with the edge condition on hover). Same component on every workstream tab and under the summary on the Plan view. Task states, each with its own color AND symbol (never color alone), legend on the map:

  | State | Color | Symbol |
  |---|---|---|
  | agent working now | `--s1` blue, solid fill, pulse, tool badge | ● |
  | waiting to merge (open PR) | `--warning` amber | ⧗ |
  | merged, waiting on a prod step | `--s5` magenta | ⇡ |
  | done | `--good` green | ✓ |
  | finished in the last 15 min | green outline | (outline) |
  | not started | dashed gray | none |
  | deferred or moved to another workstream (`status: deferred`, optional `moved_to`, `note`) | dotted gray, faded | ↷ |
  | gate: an outside signal or condition (`kind: gate`), met when done | dashed border, check when met, hollow diamond while unmet | ✓ / ◇ |

  Deferred tasks stay on the map where they were planned but leave every count and progress bar.

  The plan's task groupings are SECTIONS, never phases, groups, or stages: columns hold sections side by side, and sections run in parallel — phases would imply running serially, which they do not. The headline reads "N of M tasks done · K to go · J agents working" and never names phases; tooltips, headers, and labels say "section", never "phase", "group", or "stage"; the narrative strip keeps its data under a "Sections" label (full prose stays on the plan view). Machine keys keep their historic names (`cols`, `groups`, `narrative.phases`, `phases_line`): only the user-visible term is "section". Project-level `project.json` phases (sequential, with target dates) keep the word "phase": they are genuinely serial, not plan sections. The planning-versus-execution usage split says "kind of work" instead: planning, execution, review and coordination run in parallel, so "phase" would mislead there.

  An always-visible legend sits right under the card's intro line, above the map, in labelled mini-groups — Task status (the table above plus the amber ↻ edge for "sent back twice or more"), Agent family (only families present on the card; chip borders, badges and pills in a family hue are that family's agents: Claude blue, Cursor yellow, muse magenta, GLM green, and the rest of the entity palette), Edges (solid arrow = prerequisite done, dashed = waiting, ◇ = gate). Colour is never the only carrier: every entry is swatch plus glyph plus word, a list with an aria-label, wrapping on phones. The "Legend ⓘ" popover keeps the long text. (The earlier compact row lived below the progress bar and the chip rows, showed only five states, and never explained the family border colours — that is why it read as missing.) Running agents that map to no task do not appear in the map at all (they still appear in Running now): there is no unmapped strip.

  Blue is reserved for "working now"; do not reuse it for any stored state. Violet is not used here (too close to blue side by side). Validated: CVD ΔE 14.7 light, 9.9 dark; amber is the reserved warning status color, relieved by the symbol and the task id.

## Behavior

- Read-only on every source. Never shows prompt bodies, argv, secrets or env values. Labels only.
- Lifecycle actions are the write actions, and the destructive ones ask first: Archive opens an inline confirm popover (never `window.confirm`) naming the workstream — "Archive <name>? It moves to the Archive view; you can restore it." — with Archive and Cancel, Escape cancels, focus moves in and back; Drop uses the stronger terminal-worded confirm; bulk actions confirm once with the covered workstreams listed. Success toasts with an Undo button kept 10 s (undo posts the reverse transition; one bulk Undo restores all that changed); Restore is confirm-free with a "Restored <name>" toast. Failures toast the hint, never silent. The Current table emphasizes one primary per row (Mark done at 100%, Archive when done, Start when planned); the workstream heading repeats it as a split button with the rest in its menu. A small "Copy command" link stays beside each real button, and in read-only mode every button becomes one.
- Refresh: SSE `tick` every 2 s triggers a snapshot refetch; everything else refetches every 30 s.
- Production jobs (source `dagster`) are never in agent lists; they are a count: the live tile shows `N prod jobs` / `N prod jobs ran`.
- `?fixtures` loads `../fixtures/*.json` for offline design work.
- No health or warning cards on the page; doctor is CLI and API only. Read the problem list with `agent_dash.py doctor` or `GET /api/doctor`.
- Owner-approved exception (Linear card, now removed from the Execution views at the owner's ask): the sync state was a glyph plus a word in muted text (✓ Synced, ◔ Queued, ⚠ Sync error), never a status color or a warning card. The card code (static/cards/linear.js) is kept but no longer loaded; sync failures still belong in doctor.
- A linked workstream shows a `Linear ↗` link and its sync age (muted, exact time on hover) on the plan card header and the Where we are row; sync failures stay in doctor.

## Accessibility and phone

- Every interactive element is a real button or link with an accessible name. Clickable cards use role button with tabindex 0 and Enter/Space handling; no clickable div without role and tabindex (`tests/test_page_rules.py` pins this).
- Keyboard focus is visible and tab order follows the page. The project switcher and copy-command buttons work with Enter and Space.
- Charts carry a text takeaway: an aria-label on the svg plus a sentence naming the main takeaway; tooltips open on focus as well as hover.
- State is never color alone: every status ships a glyph plus a word (✓ Done, ⧗ waits, ⇡ on prod, ◇ gate unmet).
- Muted body text meets 4.5:1 on both themes (a computed-contrast test over `tokens.css` pins this). `prefers-reduced-motion` disables pulses and blinking.
- At 390 px no view scrolls the page sideways in either theme: the slim pinned row keeps its height (the project name wraps to two lines, pins hide, the switcher becomes a full-width sheet), tables scroll inside their own container.
